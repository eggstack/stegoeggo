Status: Ready for implementation

Roadmap: `plans/057-stego-carrier-library-and-pipeline-simplification-roadmap.md`

Audited planning baseline: `main` at `e60b801fda493ddd5e744f5de2a12d7b9489c078`

Authoritative implementation ledger to create before source edits: `plans/058-status.md`

## 1. Purpose

Correct the mathematical carrier model used by pixel-domain steganography before that machinery is extracted or exposed as a generic library API.

The current implementation computes capacity using three RGB channels per pixel, but maps logical embed positions through a permutation whose modulus is only `width * height`, then derives the RGB channel from the payload-bit index. This means capacity, embedding, and extraction do not share one exact carrier-space model. The current affine mapping is also only guaranteed to be a permutation when its multiplier is coprime to the modulus; choosing an odd multiplier does not guarantee that for arbitrary non-power-of-two dimensions.

The implementation still round-trips its own historical output because extraction mirrors the same mapping. Therefore this plan must introduce a corrected scheme without breaking existing images.

This plan owns correctness and compatibility only. It does not yet create the final generic public API.

## 4. Phase 1 — define explicit carrier schemes

Introduce a crate-internal scheme discriminator with names that make compatibility intent obvious, for example:

```rust
pub(crate) enum LsbCarrierScheme {
    LegacyV1,
    CarrierSlotsV2,
}
```

Exact names may differ, but the requirements are:

- `LegacyV1` reproduces existing pixel-index/channel-derived behavior exactly.
- The corrected scheme is a distinct code path.
- New StegoEggo LSB embeddings use the corrected scheme.
- StegoEggo extraction can probe the corrected scheme and then the legacy scheme in a bounded order.
- Legacy behavior is not silently changed in place.

Do not use payload-v3 version as a proxy for carrier scheme. Existing payload-v3 images may use the legacy carrier, and carrier extraction must succeed before payload fields can be parsed.

Do not add a permanent metadata field solely to select the carrier scheme unless implementation proves bounded probing impossible. The preferred compatibility strategy is current-scheme-first, legacy-scheme-second probing.

## 5. Phase 2 — make RGB carrier slots the exact domain

The corrected scheme must operate over actual RGB carrier slots:

```text
slot_count = width * height * 3
```

Alpha is never a carrier.

For a selected slot:

```text
pixel_index = slot / 3
channel = slot % 3
x = pixel_index % width
y = pixel_index / width
```

Use checked arithmetic before converting dimensions into `usize`. Existing resource limits should make overflow unreachable for accepted images, but the implementation must still fail closed rather than rely on wrapping multiplication.

The corrected mapping must satisfy:

```text
required_carrier_slots <= slot_count
```

before any modification occurs.

The capacity computation used for warnings/reports must call the same helper used by embedding. There must not be a separate approximate formula in `lib.rs` or warning code that can drift from the carrier implementation.

## 6. Phase 3 — use a true permutation for arbitrary dimensions

A low-allocation affine permutation is acceptable and preferred over allocating/shuffling all carrier indices, but it must be bijective over `[0, slot_count)`.

For a mapping of the form:

```text
p(i) = (a*i + b) mod m
```

require:

```text
gcd(a, m) == 1
```

where `m = slot_count`.

A bounded deterministic coefficient selection strategy is acceptable, for example:

1. derive candidate `a` and `b` from `splitmix64(seed)`;
2. normalize `a` into `[1, m)`;
3. advance deterministically until `gcd(a, m) == 1`;
4. use checked/widened multiplication or modular arithmetic that cannot overflow incorrectly on supported targets.

Special cases:

- `m == 0`: invalid/zero-capacity input, no division/modulo;
- `m == 1`: the only valid permutation maps 0 to 0;
- tiny images: return explicit skipped-capacity outcome rather than panic.

Do not claim cryptographic pseudorandomness. The purpose is deterministic dispersion with exact collision-free indexing, not a cryptographic PRP.

### Required tests

At minimum:

```text
carrier_v2_permutation_is_bijective_power_of_two
carrier_v2_permutation_is_bijective_prime_slot_count
carrier_v2_permutation_is_bijective_composite_non_power_of_two
carrier_v2_permutation_is_bijective_odd_image_dimensions
carrier_v2_permutation_different_seed_changes_order
carrier_v2_permutation_same_seed_is_deterministic
```

For small moduli, enumerate every output slot and assert exact uniqueness/range.

## 7. Phase 4 — define replication semantics exactly

The current implementation combines a fixed spread factor with multiple full-payload passes. In the corrected carrier, replication must have one unambiguous capacity model.

Preferred corrected model:

```text
replicas_per_bit = STEGO_SPREAD_FACTOR * effective_redundancy
required_slots = payload_bits * replicas_per_bit
```

Each logical bit consumes distinct carrier slots from one permutation. Extraction majority-votes the replicas for that bit.

This model is preferred because:

- required capacity is exact;
- one bit cannot overwrite another bit's carrier within the same embedding;
- additional redundancy has an explicit capacity cost;
- extraction can decode a known prefix without knowing the final payload length;
- tiled mode can retain effective redundancy 1 because tile copies already provide outer redundancy.

If implementation chooses a different model, it must prove all of the same properties and document the exact capacity equation in the status ledger.

Do not allow two redundancy passes to overwrite one another in the corrected scheme.

### Required tests

```text
carrier_v2_required_capacity_matches_exact_slots_touched
carrier_v2_one_slot_below_capacity_skips_without_modification
carrier_v2_exact_capacity_embeds_and_extracts
carrier_v2_redundancy_increases_required_capacity
carrier_v2_redundancy_roundtrips
carrier_v2_no_duplicate_slot_within_embedding
carrier_v2_alpha_channel_unchanged
```

For `no_duplicate_slot_within_embedding`, test the selected carrier indices directly through a test-only helper rather than inferring from pixel values, because a target bit may already match the original LSB and require no physical mutation.

## 8. Phase 5 — preserve legacy StegoEggo extraction

StegoEggo extraction paths that currently recover payloads from PNG/WebP pixels must support both schemes.

Preferred order:

```text
1. current CarrierSlotsV2
2. legacy LegacyV1
3. existing bounded tiled/fallback-seed logic as applicable
```

Do not multiply already-expensive seed/tile searches without accounting for resource limits. Scheme probing should be a small fixed multiplier, not an unbounded new search dimension.

The legacy helper must retain the historical mapping exactly, including any oddities. Do not “clean up” the legacy code until committed fixtures prove byte-level compatibility.

The new scheme becomes the default for new LSB embeddings only after all compatibility tests pass.

### Required tests

```text
legacy_v1_fixture_extracts_after_v2_default
legacy_v1_hmac_fixture_extracts_after_v2_default
legacy_v1_wrong_key_still_fails
legacy_v1_tiled_fixture_extracts_if_tiled_uses_legacy_mapping
new_v2_payload_extracts_before_legacy_probe
new_v2_wrong_seed_does_not_false_positive
```

Use existing CRC/HMAC payload integrity to reject false positives; do not treat arbitrary decoded bytes as success.

## 9. Phase 6 — consolidate capacity helpers

After the corrected scheme is working:

- remove duplicated LSB capacity arithmetic from higher pipeline/warning code;
- expose one crate-internal capacity helper that accepts the relevant payload bit length/configuration;
- make `EmbedOutcomeSummary.required_capacity` and `available_capacity` use one documented unit.

Preferred unit for LSB summaries after this plan: RGB carrier slots, not pixels.

If changing the unit of an already-public report field would be semver-sensitive or misleading, retain the public unit and add an internal exact-slot helper, but document the conversion explicitly. Do not silently change observable units without checking existing docs/tests.

## 10. Acceptance criteria

Plan 058 is complete only when:

1. A committed legacy LSB fixture generated by the pre-correction algorithm still extracts successfully.
2. Legacy HMAC verification behavior is preserved, including wrong-key failure.
3. The corrected scheme treats `width * height * 3` RGB channel slots as the carrier domain and never writes alpha.
4. The corrected index mapping is a proven bijection for arbitrary tested nonzero carrier counts, including non-power-of-two composite counts.
5. Capacity, embedding, and extraction use the same exact carrier-space definition.
6. Redundancy/replication has an explicit capacity cost and cannot overwrite another logical payload bit within one corrected embedding.
7. Exact-capacity input embeds and round-trips; one-slot-insufficient input returns a skipped-capacity outcome without modifying the image.
8. New StegoEggo PNG/lossless-WebP embeddings use the corrected scheme.
9. StegoEggo extraction probes corrected then legacy scheme under bounded resource limits.
10. Existing payload-v1/v2/v3 parsing remains unchanged unless a focused compatibility fix is required.
11. Existing tiled behavior remains functional; if tiled LSB is migrated to the corrected carrier in this plan, old tiled fixtures remain readable.
12. No JPEG, rights-policy, metadata, public generic API, dependency, CI, or release changes are included.
13. Focused LSB tests pass.
14. `./scripts/check.sh` passes before Plan 058 is marked complete.
15. `plans/058-status.md` records exact implementation commits, commands, fixtures, and any intentionally retained legacy limitations.
